# 维度优先的双层知识检索方案

## 可行性评估
- 可行，而且比“全文简单切片”更适合当前系统。数据库里已经有 `reading_items`：长文本维度 245 条、七步子问题 423 条、四步子问题 381 条，这些就是高质量语义入口。
- DeepSeek 官方 2026-04-24 文档确认 V4 Flash/Pro 支持 1M context，且 API 可直接使用 `deepseek-v4-flash`；但 1M 上下文不等于可以把全库无脑塞进去。更合理的是：用数据库先选中“维度证据包”，再把少量原文窗口放进大上下文做核验、对比和写作。
- 当前限制是原文覆盖率：本地库 547 条 `bib_entries` 中只有 61 条有 `source_file_id`。所以首版必须把原文比对设计成“有原文则核验，无原文则降级到精读结果/产物，并明确标记证据等级”。

来源：[DeepSeek V4 Preview Release](https://api-docs.deepseek.com/news/news260424)

## 双层索引结构
- 第一层：维度语义层，不做机械切片。
  - 索引单位来自 `reading_items`，粒度为长文本维度、七步/四步子问题，必要时包含 step 总结。
  - 每个单位保存 `bib_entry_id`、`job_id`、`reading_item_id`、`mode`、`dimension_key`、`dimension_label`、`parent_key`、`content`、`created_at`、`source_confidence`。
  - FTS 检索字段为标题、作者、摘要、维度名、问题名、维度内容、用户标签/笔记。
- 第二层：原文证据层，不作为主检索入口，而作为维度命中后的比对参考。
  - 对有 `source_file_id` 的 PDF/Markdown 建立原文结构索引：页码、章节标题、段落、字符偏移、局部上下文。
  - 存储基础 atom，例如 paragraph/page/section，不直接把它们当最终 chunk。
  - 命中维度后，再按维度关键词、研究对象、方法名、变量名、引用标签，在同一 `bib_entry_id` 的原文 atom 中组装动态窗口。
  - 动态窗口默认 2-3 段前后文或 3000-6000 字符，必要时升级为整节或整篇进入 1M 上下文。

## 检索流程
- 用户问题先由 LLM 生成结构化 DSL：研究主题、目标维度、关键词、排除词、文献范围、年份/期刊/标签过滤。
- 后端只执行白名单 DSL，先查第一层维度索引，返回最相关的维度单位。
- LLM 阅读维度命中结果后输出：
  - 当前已知结论
  - 证据缺口
  - 需要回看哪些文献原文
  - 每篇原文要查哪些术语或章节
- 后端据此查询第二层原文索引，组装原文窗口。
- LLM 对比“精读维度结论 vs 原文窗口”，标记：
  - `supported`：原文支持
  - `overstated`：精读表述过度
  - `missing_context`：需要补充上下文
  - `contradicted`：原文不支持或相反
  - `source_unavailable`：无原文，只能引用精读结果
- 多跳继续时，新一轮查询不再只看用户问题，而是带着上一轮缺口、新术语、新引用关系继续挖。

## 上下文预算策略
- 1M context 用于“深度核验与写作”，不是替代检索。
- 问答默认控制在 300k-500k token：
  - 维度命中 20-50 条
  - 原文窗口 20-80 个
  - 会话轨迹和证据表保留摘要
- 自动综述可放宽到 600k-800k token：
  - 先生成证据图谱和章节大纲
  - 每章单独检索原文窗口
  - 最终写作时只放入该章相关证据包
- 小范围场景可升级：若选中文献不超过 3 篇且原文总量可控，可直接放入整篇原文做核验。

## 数据库落地
- 新增 `knowledge_dimension_units`：从 `reading_items` 派生，可重建。
- 新增 `knowledge_source_docs`：记录原文/产物来源、hash、提取状态。
- 新增 `knowledge_source_atoms`：页、节、段落级原文 atom。
- 新增 `knowledge_source_atoms_fts`：FTS5 trigram，用于中英文混合原文查找。
- 新增 `knowledge_unit_source_links`：维度单位与原文窗口的懒加载映射，保存核验结果。
- 新增 `knowledge_sessions / knowledge_steps / knowledge_evidence`：保存多轮探索、查询 DSL、证据链和最终回答。
- 派生索引表默认不导出 `.dra`，会话和证据快照导出；导入后可重建索引。

## 默认规则
- 默认只检索每篇文献最新成功的精读结果；历史版本可作为高级选项。
- 正式综述引用优先级：原文窗口 > 精读维度且已原文核验 > 参考文献/引用命中 > 历史产物。
- 没有原文的文献可以参与观点发现，但综述中必须标注为“基于精读结果，未回看原文”。
- 后续新增精读任务时，建议在生成 `reading_items` 的同时保存原文锚点，这会显著提高维度到原文的回查准确率。
