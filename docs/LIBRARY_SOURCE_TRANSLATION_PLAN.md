# 文献库原文与全文翻译联动计划

> 状态：实施中
> 日期：2026-05-21

## 目标

围绕 `bib_entries` 文献档案补齐原文与语言信息，让用户能够：

1. 在“我的文献库”看到当前文献绑定的 PDF 或 Markdown 原文。
2. 在文献库中看到并维护文献语言类型。
3. 点击绑定原文进行预览或下载。
4. 在“全文翻译”页看到所有已标注为英文、且已绑定 PDF/Markdown 原文的文献，并直接发起翻译。

## 现状

- `bib_entries.source_file_id` 已经指向上传到 `files` 表的物理原文。
- 文献库接口已经返回源文件 ID 和文件名，但前端只展示文件名。
- `/api/download/*` 当前面向任务产物 `artifacts`，不能直接复用为上传原文下载接口。
- PDF 元数据抽取流程能够得到 `language`，但 `bib_entries` 还没有持久语言字段。
- 全文翻译页已有可翻译文献列表，但英文筛选仍依赖前端标题启发式判断。

## 方案

### 数据模型

在 `bib_entries` 增加 `language` 字段，首期使用如下值：

- `en`：英文
- `zh`：中文
- `other`：其他语言
- `NULL`：未标注

该字段属于用户数据。实施时需要同步：

- SQLAlchemy 模型
- Alembic migration
- `.dra` 导入导出 schema version
- `docs/DATABASE_SCHEMA.md`

### 后端接口

1. 文献库列表与详情接口返回：
   - `language`
   - `source_file_type`
   - 现有 `source_file_id`、`source_file_name`
2. 文献库编辑接口允许更新语言字段。
3. 上传文件路由新增受鉴权保护的原文访问接口：
   - 原文预览
   - 原文下载
4. 全文翻译列表接口只返回：
   - 当前用户的文献
   - `language == "en"`
   - 已绑定 PDF 或 Markdown 原文

### 前端交互

1. “我的文献库”列表展示语言标签和绑定原文格式。
2. 文献详情区展示原文文件名、格式、语言标签，以及预览/下载按钮。
3. 文献详情编辑区提供语言选择框，允许用户修正自动识别结果。
4. “全文翻译”页移除标题猜测英文的筛选逻辑，列表直接展示后端返回的英文文献。

## 自动标注策略

- 新建字段后，历史文献默认保持未标注，避免错误批量猜测。
- 精读流程中若 PDF 元数据抽取返回可信语言，且用户尚未标注文献语言，则写入 `bib_entries.language`。
- 用户手动修改后的语言值不应被后续自动抽取覆盖。

## 验收清单

1. 绑定 PDF 的文献可在文献库预览并下载原文。
2. 绑定 Markdown 的文献可在文献库预览并下载原文。
3. 未绑定原文的文献显示清晰空态，不暴露无效操作。
4. 非本人上传文件不能通过原文接口访问。
5. 文献语言可在文献库保存并刷新保留。
6. 全文翻译页只显示英文且具有 PDF/Markdown 原文的文献。
7. 后端路由注册检查、相关后端单测、前端 lint/build 按本次改动范围执行。
