## Summary
- 当前仍在 Plan Mode，不能直接写入 `docs/` 或改提示词文件；实施开始后第一步保存文档。
- 先新增 `docs/KNOWLEDGE_QA_REVIEW_DESIGN.md`，记录“维度优先 + 原文回看”的双层知识检索方案，并在 `docs/README.md` 的“方案设计文档”中加入入口。
- 再新增 `docs/LONG_READING_PROMPT_REFINEMENT_PLAN.md`，记录本轮提示词改进方案，避免未来只改架构、不改精读数据质量。
- 依据 DeepSeek 官方 2026-04-24 文档，V4 Flash/Pro 支持 1M context，可用于“原文回看与核验”，但精读维度仍应输出高密度、可检索、可回查的证据卡片。来源：[DeepSeek V4 Preview Release](https://api-docs.deepseek.com/news/news260424)。

## Key Findings
- 现有长文本提示词过短，普遍只要求“分析/评估/指出局限”，缺少统一输出契约，导致 `reading_items.content` 难以稳定用作第一层语义索引。
- `methodology.md` 明确要求“高中生都能听懂的详细解读”，会放大篇幅，不利于后续知识库检索，应改为专家压缩式输出。
- `ai_template_generator.py` 当前只取论文前 `8000` 字符，模型还是 `deepseek-chat`，元提示词偏“案例分析维度体系”，未要求生成可检索、可原文回查的维度提示词。
- `PaperCache.get_full_prompt_prefix()` 实际发送全文，`get_truncated_text()` 没被长文本精读主链路使用；因此精读提示词可以要求模型保留原文定位线索，而不是担心看不到全文。

## Prompt Refactor
- 给所有 `prompts/long/*.md` 统一加入“维度输出契约”：
  - `核心判断`：1-2 句，最多 120 字。
  - `证据要点`：3-6 条，每条包含原文关键词、表/图/章节/变量/方法名等可回查锚点。
  - `分析结论`：2-4 条，只写该维度直接相关内容。
  - `原文回查线索`：列出建议回看的章节、表格、变量名、模型名、关键词。
  - `可信度与缺口`：说明证据强/中/弱，以及缺失信息。
- 全局约束：
  - 不写铺垫、背景常识和泛泛评价。
  - 不把外部知识当成论文内容；若原文没有证据，明确写“原文未见直接证据”。
  - 保留关键英文术语、变量符号、表格编号、模型设定、年份、样本范围。
  - 每个维度输出控制在 500-900 中文字，`methodology/results` 可放宽到 1200 字。

## Dimension-Specific Changes
- `overview.md`：从“核心贡献”改为“研究问题-贡献-证据边界”，要求提取研究对象、X/Y、核心问题、贡献类型、最强证据锚点。
- `theory.md`：区分作者明示理论、隐含理论、未覆盖但必要理论；输出理论链条和理论缺口，不扩写理论史。
- `methodology.md`：删除“高中生都能听懂”；改为识别研究设计、因果策略、对照/反事实、关键威胁、作者处理方式、剩余风险。
- `data_source.md`：强制抽取数据来源、样本单位、时间范围、地区范围、样本筛选、缺失处理、代表性边界。
- `variable_measurement.md`：用表格输出“概念-变量-度量方式-数据来源-测量风险-原文锚点”。
- `identification_assumptions.md`：按“假设-作者证据-可能违反-影响方向-可补充检验”组织。
- `results.md`：要求绑定表格/模型/系数/显著性/效应大小，禁止把相关性过度写成因果。
- `mechanism.md`：区分机制假说、机制检验、异质性证据、替代机制和证据缺口。
- `robustness.md`：按“担忧-检验-结果-是否解除担忧-剩余问题”输出。
- `external_validity.md`：明确人群、地区、时期、制度环境、方法条件的推广边界。
- `contributions_limitations.md`：贡献最多 3 点，局限按“对结论可靠性影响”排序。
- `writing_quality.md`：弱化主观评价，改为论证结构、概念一致性、图表可读性、引用完整性和可复用片段。

## Auto-Generated Prompt Meta-Prompt
- 修改 `backend/services/ai_template_generator.py`：
  - `MODEL` 改为 `deepseek-v4-flash`。
  - `MAX_PAPER_CHARS` 从 `8000` 提升到更适合 V4 Flash 的预算，例如 `60000`，并优先保留摘要、引言、方法、结果、结论。
  - 降低 `temperature` 到 `0.3`，让生成维度更稳定。
- 重写 `META_PROMPT_TEMPLATE`：
  - 目标从“案例分析维度体系”改为“可检索、可核验、可支撑综述写作的精读维度体系”。
  - 每个生成维度必须包含：分析对象、证据锚点要求、输出结构、原文回查线索、禁止泛化规则。
  - `prompt_content` 必须内置统一输出契约，不能只写三个抽象子问题。
  - 要求维度之间低重叠：理论、数据、方法、结果、机制、外部有效性、贡献局限各司其职。
- 保持现有保存结构不变：仍写入 `dim_name / description / default_question / prompt_content / group_name`，不先新增数据库字段。
