# 对比页 AI 综述与跨步骤选择改造规划

## 1. 背景

当前 `七步对比` 与 `四步对比` 页面的“AI 综述”交互已经不是第一次暴露问题，现阶段至少有两类明显缺陷：

1. `生成 AI 综述` 按钮长期处于不可点击状态，用户不知道到底缺了什么条件。
2. `跨层模式` / `跨步骤模式` 按钮引入了额外状态机，但没有形成清晰、稳定的选择体验，反而会破坏已有的筛选与勾选逻辑。

本次先规划，不立即实施。目标是先把交互和状态模型定义清楚，再决定是否编码落地。

## 2. 当前问题复盘

### 2.1 AI 综述按钮长期不亮

当前前端实现中，`七步对比` 与 `四步对比` 都把按钮可用条件写成：

- 已选择步骤
- 已选择文献
- 已选择至少一个子问题

也就是：

- `selectedStep` 非空
- `selectedPapers.length > 0`
- `selectedSubQuestions.size > 0`

这会带来两个体验问题：

1. 页面没有明确提示“还差什么条件”，用户只看到按钮一直灰着。
2. 选中条件与“跨层模式”耦合后，普通选择流程很容易被打断。

另外，后端 `/api/compare/analyze` 还有一个硬约束：

- 对比分析至少需要 `2` 篇文献。

因此，前端当前“只要选了 1 篇也可以尝试点亮”的语义本身就和后端不一致。

### 2.2 跨层模式按钮设计有误

当前 `七步对比` 与 `四步对比` 都增加了：

- `跨层模式` 按钮
- 隐藏/展开的跨层选题面板
- 独立的 `crossMode`
- 独立的 `crossSelected`
- 对 `updateUI()` 和 `btnSynthesis.onclick` 的重写

这套设计的问题在于：

1. 普通模式与跨层模式共用同一个页面，但却维护两套不同的选择状态。
2. 切换模式时会清空或覆盖已有子问题选择，导致“看上去像没选上”。
3. 用户真正想要的是“跨步骤累计选题”，不是“切到另一个特殊模式页面”。
4. 这套模式按钮没有提供明确的已选数量反馈，也没有形成自然的步骤切换路径。

结论：

- 现有 `跨层模式` 按钮应视为错误方向，不应继续强化。

## 3. 目标

本次改造目标有两个：

### 3.1 AI 综述按钮可用逻辑清晰化

用户必须明确知道：

- 目前已选了几篇文献
- 当前步骤是否已选
- 已选了几个问题
- 距离可生成综述还差什么

### 3.2 跨步骤选择改成“累计选择”，而不是“特殊模式”

用户期望的是：

1. 在第一步选中某个问题
2. 页面提示：`已选中 1 个问题`
3. 切换到第二步再选一个问题
4. 页面提示：`已选中 2 个问题`
5. 点击 `全部取消`
6. 页面提示：`已选中 0 个问题`

这说明需求本质是：

- **跨步骤累计选题**

而不是：

- **进入一个独立的跨层模式**

## 4. 推荐交互方案

### 4.1 去掉 `跨层模式` 按钮

在 `七步对比` 和 `四步对比` 页面中：

- 删除 `跨层模式` / `跨步骤模式` 按钮
- 删除额外的跨层面板
- 删除 `crossMode`
- 删除 `crossSelected`
- 删除对 `updateUI()` 和 `btnSynthesis.onclick` 的运行时重写

保留唯一的选择模型：

- `selectedPapers`
- `selectedStep`
- `selectedQuestions`

但这里的 `selectedQuestions` 不再仅代表“当前步骤内勾选”，而是：

- **全局累计的已选问题集合**

### 4.2 问题选择从“仅按文本”升级为“带步骤上下文”

如果要支持跨步骤累计，就不能再只把问题存成纯文本，比如：

- `1. 研究主题与核心结论`

否则不同步骤里出现相似子问题时会冲突。

建议统一使用复合键：

- `quant.step1::1.研究主题与核心结论`
- `qual.step2::2.理论视角与核心概念`

前端展示时仍显示用户可读标题，但内部状态要保留：

- 模式
- 步骤
- 子问题标题

建议结构：

```ts
type SelectedQuestion = {
  questionKey: string
  stepId: string
  stepLabel: string
  questionLabel: string
}
```

### 4.3 页面顶部增加“已选状态栏”

在步骤选择控件附近增加一个固定状态区，持续显示：

- 已选文献数
- 当前步骤
- 已选问题数

例如：

- `已选文献 3 篇`
- `当前步骤：第二步：理论框架评估`
- `已选问题 2 个`

同时在右侧放两个动作：

- `生成 AI 综述`
- `全部取消`

### 4.4 “全部取消”的语义

用户已经明确说明：

- `全部取消` 应取消所有步骤中的所有已选问题
- 取消后提示变成 `已选中 0 个问题`

因此这里不能只是“取消当前步骤的勾选”，而必须是：

- 清空整个全局已选问题集合

### 4.5 当前步骤切换后的行为

切换步骤时：

- 不清空全局已选问题
- 只切换当前表格展示的步骤内容
- 表格中仅当前步骤下、已被选中的那些问题继续显示勾选状态

这意味着：

- `selectStep()` 不应再执行 `selectedSubQuestions.clear()`

## 5. AI 综述按钮启用规则

### 5.1 正确规则

`七步对比` 与 `四步对比` 的 AI 综述按钮建议按以下规则启用：

1. 至少已选 `2` 篇文献
2. 至少已选 `1` 个问题

不再要求“当前步骤下必须重新选过一次”，因为问题可以跨步骤累计。

因此启用条件应改为：

- `selectedPapers.length >= 2`
- `selectedQuestions.size >= 1`

### 5.2 按钮旁提示文案

按钮不可用时，建议显示明确原因：

- `请至少选择 2 篇文献`
- `请至少选择 1 个问题`

如果两者都未满足，则同时提示或拼接提示。

### 5.3 点击生成时的请求模型

请求发给 `/api/compare/analyze` 时，应携带：

- 当前模式：`cross`
- 所有已选问题
- 每个问题的所属步骤
- 所有选中的文献

这样后端才能真正生成跨步骤综述，而不是被迫假装它仍然属于“单一步骤多问题”。

## 6. 前端状态模型改造建议

### 6.1 当前问题

当前页面状态分裂为两套：

- 普通选择：
  - `selectedStep`
  - `selectedSubQuestions`
- 跨层模式：
  - `crossMode`
  - `crossSelected`

这会导致：

- 勾选状态容易丢失
- 切换模式后按钮状态不可预测
- 同一按钮在不同模式下走不同请求语义

### 6.2 建议的新模型

统一为：

- `selectedStep`
- `selectedPapers`
- `selectedQuestionsByKey`

其中：

- `selectedStep` 只决定当前表格展示哪个步骤
- `selectedQuestionsByKey` 代表全局累计问题选择
- 页面任何地方都不再有“特殊模式开关”

### 6.3 表格勾选逻辑

在当前步骤表格中：

- 每一行 checkbox 对应一个全局问题键
- 勾选时加入全局集合
- 取消时从全局集合移除

步骤切换后：

- 只渲染当前步骤问题
- 但如果某行对应的问题键已在全局集合中，则保持勾选

## 7. 后端接口规划

### 7.1 当前后端能力

当前 `/api/compare/analyze` 已经支持：

- `mode = single`
- `mode = multi`
- `mode = cross`

且 `mode = cross` 时会调用：

- `build_cross_dim_prompt(...)`

这说明后端已经有一定的跨步骤综述能力基础，不需要从零重做。

### 7.2 当前后端不足

当前前端传给后端的数据结构更偏向：

- 单步骤
- 当前步骤里的若干子问题

如果要做真正的“跨步骤累计选择”，推荐前端传给后端的 `subQuestions` 变成：

- 带步骤前缀的问题键

例如：

- `[第一步] 1.研究主题与核心结论`
- `[第二步] 2.理论框架与核心变量`

这样后端 `mode = cross` 可以直接按步骤分组生成综述。

### 7.3 推荐后端保持兼容

建议后端保持三种模式兼容：

- `single`
- `multi`
- `cross`

但前端：

- 长期不再暴露“跨层模式按钮”
- 当用户跨步骤累计选择时，自动使用 `cross`
- 当用户只在单一步骤里选了多个问题时，可继续使用 `multi`
- 当用户只选了一个问题时，使用 `single`

## 8. 页面文案规划

### 8.1 顶部提示

建议在步骤选择区域附近增加一条提示：

- `已选中 0 个问题`
- `已选中 1 个问题`
- `已选中 2 个问题`

这是用户已经明确提出的核心需求，必须直观显示。

### 8.2 按钮文案

当前：

- `跨层模式`
- `生成 AI 综述`

建议调整为：

- 删除 `跨层模式`
- 保留 `生成 AI 综述`
- 新增 `全部取消`

### 8.3 空状态文案

如果未选问题，建议给出：

- `请先在任意步骤中勾选要纳入综述的问题`

如果文献不足 2 篇：

- `AI 综述至少需要 2 篇文献`

## 9. 适用页面

本次规划适用于：

- `frontend/public/compare_7step.html`
- `frontend/public/compare_4step.html`

不直接影响：

- `compare_long.html`

原因：

- 长文本对比的单位是“维度”，不是带编号子问题的分步结构
- 其选择模型与七步法、四步法不同

## 10. 分阶段实施建议

### 第一阶段：修正确认规则

先修最明显问题：

- 按钮启用规则改为“至少 2 篇文献 + 至少 1 个问题”
- 增加原因提示

### 第二阶段：去掉跨层模式按钮

- 删除独立 `crossMode`
- 删除 `crossSelected`
- 删除跨层面板

### 第三阶段：实现跨步骤累计选择

- 问题键改为“步骤 + 子问题”复合键
- 保持切步骤后不丢已选问题
- 增加顶部 `已选中 N 个问题`
- 增加 `全部取消`

### 第四阶段：统一生成逻辑

- 单问题 -> `single`
- 同一步骤多问题 -> `multi`
- 跨步骤多问题 -> `cross`

## 11. 验收标准

### 11.1 七步对比 / 四步对比共同验收

- 至少选中 2 篇文献后，不再因为模式切换导致按钮异常灰掉
- 勾选 1 个问题后，顶部显示 `已选中 1 个问题`
- 切换到其他步骤再勾选 1 个问题后，顶部显示 `已选中 2 个问题`
- 点击 `全部取消` 后，顶部显示 `已选中 0 个问题`
- 切换步骤后，之前已选的问题仍保留在全局选择集合中
- 生成 AI 综述时，请求模式与用户选择形态一致

### 11.2 交互体验验收

- 页面上不再存在让用户困惑的 `跨层模式` 按钮
- 按钮是否可用有清晰理由
- 已选数量始终可见
- 用户无需理解内部模式，就能自然完成跨步骤综述选择

## 12. 当前结论

当前 `跨层模式` 不是“功能没做完”，而是交互方向本身不对。

更合理的方案是：

1. 删除模式按钮
2. 保留普通页面结构
3. 把问题选择升级为“跨步骤累计选择”
4. 把 `AI 综述` 的启用条件和提示做清楚

这样既能满足你想要的“先选一步、再选下一步、累计计数、全部取消”的流程，也能复用现有后端 `mode = cross` 的能力。

## 13. 本文档范围说明

本文档仅用于规划，不代表当前功能已经修复。

当前阶段：

- 不修改前端页面
- 不修改后端接口
- 先确认交互方案，再决定是否实施
