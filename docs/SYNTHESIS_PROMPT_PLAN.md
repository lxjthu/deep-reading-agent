# 文献综述提示词重构规划

## 1. 背景

当前系统中的文献综述能力主要出现在以下场景：

- `七步对比` 的单问题 / 多问题综述
- `四步对比` 的单问题 / 多问题综述
- `七步 / 四步` 的跨步骤综述
- `长文本对比` 的单维度 / 多维度综述

目前这些综述提示词并没有纳入“提示词管理”，而是直接硬编码在后端：

- `backend/routers/compare.py`

这导致两个问题：

1. 提示词无法在前端统一管理、快速迭代。
2. 综述输出质量问题难以区分到底是：
   - 提示词设计不合理
   - 引用锚点设计不合理
   - 参考文献目录生成逻辑不合理
   - 底层文献元数据本身缺失

本次先做规划，不直接修改实现。

## 2. 当前暴露的问题

### 2.1 引用锚点和参考文献目录对不上

你反馈的典型问题是：

- 正文里出现类似 `（文献1）`、`（文献2）`
- 但底部参考文献目录是按真实题录元数据生成的
- 两者无法一一对应

这说明当前提示词虽然要求模型使用“作者-年份”格式，但模型并没有稳定照做。

根因在于：

- 系统目前只是把论文头部写成 `【标题 (作者, 年份)】` 一类文本
- 但没有为模型提供**强约束、可复用、唯一且明确的引用锚点**
- 模型在多篇对比时容易退化成 `文献1 / 文献2 / 某研究` 这类泛化指代

### 2.2 参考文献目录缺作者

你给出的例子里：

- `佚名 (None). 生态产品价值实现的中国经验……`

这类问题**不完全是提示词问题**。

原因是底部参考文献目录不是模型生成的，而是系统程序拼接的：

- `compare.py -> build_reference_list(...)`

其当前逻辑是：

- 没有作者就填 `佚名`
- 没有年份就会出现 `None`

因此，这个问题更接近：

- 文献元数据不完整
- 系统在引用和参考文献拼接时缺少降级策略

### 2.3 当前综述提示词没有分层

现在后端里有多套构造函数：

- `build_single_prompt`
- `build_multi_prompt`
- `build_cross_dim_prompt`
- `build_long_single_prompt`
- `build_long_multi_prompt`
- 以及通用 `SYSTEM_PROMPT`

这些提示词虽然已经能工作，但还存在以下问题：

- 没有统一的“引用规范层”
- 没有显式禁止使用 `文献1 / 文献2`
- 没有强制引用必须和给定锚点完全一致
- 没有明确区分：
  - 引文写法
  - 内容组织
  - 禁止项
  - 失败兜底

## 3. 改造目标

本次文献综述提示词重构的目标如下：

1. 将综述提示词纳入提示词管理系统。
2. 将“内容生成提示词”和“引用约束提示词”拆分。
3. 保证正文引用标注能和系统自动生成的参考文献目录对应。
4. 降低 `文献1 / 文献2` 这类错误引用形式的出现概率。
5. 为后续迭代保留前端可编辑能力。

## 4. 核心原则

### 4.1 引用锚点必须由系统提供，不能让模型自由发明

未来应由系统为每篇文献显式提供：

- 标准标题
- 作者列表
- 年份
- 唯一的引用锚点

例如：

- `CITE_KEY: 朱竑等, 2023`
- `CITE_KEY: 逯浩, 年份缺失`

或者更规范地拆成结构：

- `citation_label_cn`
- `citation_label_en`
- `authors`
- `year`

提示词中必须明确要求：

- 正文中的所有引用只能使用系统提供的 `citation_label`
- 禁止使用 `文献1 / 文献2 / 上述研究 / 某文`

### 4.2 提示词不负责生成参考文献目录

这条原则要继续保留：

- 参考文献目录必须由系统程序生成
- 不允许让模型自由编造参考文献条目

原因：

- 模型极易漏作者、错年份、乱补期刊名
- 参考文献目录必须和数据库中的结构化元数据一致

### 4.3 提示词只负责“正文如何引用”

提示词的职责应该收窄为：

- 告诉模型如何组织学术综述内容
- 告诉模型如何使用系统提供的引用锚点
- 告诉模型禁止哪些引用形式

而不是让模型自己决定参考文献格式。

## 5. 当前问题的拆解结论

### 5.1 “正文里只有文献1、文献2”

这主要属于：

- **提示词设计问题**

需要通过以下方式解决：

- 提供明确引用锚点
- 强化禁止项
- 增加输出验收约束

### 5.2 “参考文献目录缺作者、年份是 None”

这主要属于：

- **元数据质量问题**
- **程序化参考文献拼接问题**

需要单独处理：

- 元数据补全
- 年份缺失兜底策略
- 作者缺失兜底策略

因此，这部分不能只靠提示词修复。

## 6. 提示词管理的纳入方案

### 6.1 新增提示词类型

建议在提示词系统中新增一个新的 `prompt_type`：

- `synthesis`

而不是继续把综述提示词散落在 `compare.py` 里。

### 6.2 建议的提示词槽位

建议至少增加以下固定槽位：

- `synthesis.system`
  - 通用系统角色设定
- `synthesis.citation_guard`
  - 引用规范约束
- `synthesis.compare_single`
  - 七步/四步单问题综述
- `synthesis.compare_multi`
  - 七步/四步同一步骤多问题综述
- `synthesis.compare_cross`
  - 七步/四步跨步骤综述
- `synthesis.long_single`
  - 长文本单维度综述
- `synthesis.long_multi`
  - 长文本多维度综述

这样做的好处：

- 结构清晰
- 前端可管理
- 后端逻辑可组合

## 7. 提示词结构规划

### 7.1 推荐从“单一长提示词”拆成两层

推荐拆成：

1. **系统层**
   - 定义角色、总体风格、真实性约束
2. **任务层**
   - 针对当前综述类型定义结构和输出要求

同时在拼装 prompt 时插入一段固定的：

3. **引用约束层**
   - 明确每篇文献的引用锚点
   - 明确禁止使用 `文献1 / 文献2`

### 7.2 推荐的引用约束层内容

这层不建议让用户完全自由编辑，至少应有清晰默认模板。

建议包含：

- 以下每篇文献都附带唯一引用标签
- 正文引用只能使用这些标签
- 如果没有作者，则使用系统指定的降级标签
- 绝对禁止使用：
  - `文献1`
  - `文献2`
  - `第一篇文献`
  - `第二篇研究`
  - `上述研究`

### 7.3 推荐的任务层结构

无论是单问题、多问题还是跨步骤综述，都应拆成明确模块：

- 写作任务
- 结构要求
- 引用要求
- 禁止项
- 文献输入

而不是把所有要求糅成一段自然语言。

## 8. 后端拼装策略规划

### 8.1 当前模式

当前 `compare.py` 是每种综述模式各自拼一个完整 prompt。

### 8.2 推荐模式

后续建议改成：

- `system_prompt = synthesis.system`
- `citation_guard = synthesis.citation_guard`
- `task_prompt = synthesis.compare_single / compare_multi / compare_cross / long_single / long_multi`

然后由代码统一拼成：

```text
[system prompt]

[citation guard]

[task prompt]

[paper payload]
```

这样后续如果只想修“引用规范”，不用碰每一种综述模板。

## 9. 引用锚点设计规划

### 9.1 为什么现在会失控

现在给模型的论文头部大致是：

- `【标题 (作者, 年份)】`

这对模型来说不够强，尤其多篇对比时，它会自己简写。

### 9.2 推荐的锚点输出结构

建议每篇文献输入时显式给出：

```text
【文献标识】
- title: ...
- citation_label: （朱竑等，2023）
- authors: [...]
- year: 2023
- journal: 管理世界
```

或英文文献：

```text
【文献标识】
- title: Firm Credit Constraints and Electronic Payments
- citation_label: (Armstrong, 2006)
```

提示词再明确要求：

- 正文引用必须逐字复用 `citation_label`

### 9.3 年份缺失时的规划

对于没有年份的记录，不建议直接输出 `(None)`。

推荐后续程序层做统一降级：

- 中文：`（作者，年份缺失）`
- 英文：`(Author, n.d.)`

但这是程序层和元数据层要处理的，不是纯提示词能解决的。

## 10. 参考文献目录规划

### 10.1 继续程序化生成

参考文献目录仍由后端程序生成。

### 10.2 需要额外改造的点

后续应单独处理以下逻辑：

- `year is None` 时不要直接显示 `None`
- 无作者时不要只显示 `佚名`，应尽可能从题录或 PDF 元数据补全
- 作者缺失、年份缺失的条目应有更规范的兜底格式

### 10.3 与提示词的边界

本次提示词重构只解决：

- 正文引用标注形式

不直接解决：

- 元数据缺失
- 参考文献条目补全

这两块需要单独规划和实施。

## 11. 前端提示词管理页面规划

### 11.1 新增一个提示词类型分组

在“提示词管理”中新增：

- `文献综述`

对应 `prompt_type = synthesis`

### 11.2 展示槽位

下拉中可选择：

- 通用系统提示
- 引用规范约束
- 单问题综述
- 多问题综述
- 跨步骤综述
- 长文本单维度综述
- 长文本多维度综述

### 11.3 管理方式

沿用现有提示词中心模式：

- 系统默认
- 用户个人覆盖

这样后续你就可以直接在提示词管理里调综述写作风格，而不需要再改代码。

## 12. 分阶段实施建议

### 第一阶段：提示词规划入库

目标：

- 新增 `synthesis` 提示词类型
- 定义固定槽位
- 把默认模板纳入提示词管理

### 第二阶段：后端改为组合式拼装

目标：

- `compare.py` 不再硬编码完整长 prompt
- 改为读取 `synthesis.*` 提示词槽位

### 第三阶段：引用锚点强化

目标：

- 系统为每篇文献生成明确 `citation_label`
- 提示词强制模型复用

### 第四阶段：参考文献目录单独修复

目标：

- 修正 `None`
- 修正缺作者时的兜底格式
- 和元数据补全过程联动

## 13. 验收标准

### 13.1 提示词层

- 综述提示词全部进入提示词管理系统
- 前端能看到并编辑 `synthesis` 类型的各个槽位
- 后端综述逻辑不再依赖硬编码长字符串

### 13.2 输出层

- 正文引用不再出现 `文献1 / 文献2`
- 正文引用格式稳定对齐系统提供的引用锚点
- 参考文献目录继续由程序生成

### 13.3 边界认知

即使提示词层完成，如果文献元数据仍缺失，也可能继续出现：

- 作者缺失
- 年份缺失

但表现应是规范的兜底格式，而不是裸露的 `None`。

## 14. 当前结论

当前这个问题不能简单归结为“提示词写坏了”，更准确地说是三层耦合问题：

1. 综述提示词没有纳入统一管理
2. 引用锚点设计不够强，模型自由发挥成 `文献1 / 文献2`
3. 参考文献目录依赖的底层元数据不完整

因此，正确顺序应该是：

1. 先把综述提示词规划成 `synthesis` 类型并纳入提示词管理
2. 再把引用锚点机制做强
3. 最后单独修参考文献目录和元数据补全

## 15. 本文档范围说明

本文档仅用于规划，不代表当前已经实施。

当前阶段：

- 不修改 `compare.py`
- 不修改提示词中心
- 不修改参考文献目录生成逻辑
- 先确认方案，再进入测试规划和实施阶段
